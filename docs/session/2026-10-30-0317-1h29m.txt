⏺ Задача 2.2 отмечена выполненной (`0e47c9f`).
  
  Теперь про комментарий в `settings.py`.
  
  ```python
  # Read-only fields (id) stay out of request bodies: the frontend sends Event without an id.
  "COMPONENT_SPLIT_REQUEST": True,
  ```
  
  **Откуда берётся проблема**
  
  `EventSerializer` один и для ответа, и для запроса. В нём `id` помечен `read_only`: сервер его выдаёт и никогда не принимает. По умолчанию drf-spectacular делает из этого одну схему `Event`. В ней `id` отмечен как `readOnly: true` и при этом попадает в `required`, потому что в ответе он всегда есть.
  
  В OpenAPI 3.0 у `readOnly` есть оговорка: свойство нужно только в ответе. Но генератор типов `openapi-typescript` её не применяет и делает одну TypeScript-схему:
  
  ```ts
  Event: { readonly id: number; title: string; ... }
  ```
  
  Тело запроса `POST` ссылалось на ту же схему. Поэтому `vue-tsc` требовал при создании события передать `id`, которого у клиента нет. Это была ошибка в `create-event.ts` и в тесте `client.test.ts`: `Property 'id' is missing`.
  
  **Что делает настройка**
  
  `COMPONENT_SPLIT_REQUEST: True` просит генератор описывать запрос и ответ отдельными схемами:
  
  - `Event` — для ответа, с `id`;
  - `EventRequest` — для тела запроса, без read-only полей.
  
  `create-event.ts` теперь принимает `components["schemas"]["EventRequest"]`, и клиенту не нужен лишний `id`.
  
  **Побочный эффект**
  
  Схемы запросов получают суффикс `Request`, поэтому `Login` стал `LoginRequest`. Мне пришлось поправить одну строку в `login.ts`. Изменение компактное: `LoginRequest` — просто новое имя той же схемы.
  
  **Почему не обошёл иначе**
  
  - Можно было `Omit<Event, "id">` на фронтенде. Но правило 3 `frontend/AGENTS.md` требует брать типы API из схемы, а не собирать руками.
  - Можно было завести отдельный write-serializer на сервере. Это лишний код ради того, что выражается одной настройкой.
  
  Настройка действует на все будущие эндпоинты, так что `Registration`, например, не потребует отдельной возни с `id`. Комментарий в коде можно сократить, если он кажется тебе слишком подробным, но по сути он описывает именно это.
