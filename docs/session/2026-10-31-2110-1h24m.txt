⏺ Task 3.1 is done and committed as `2f59ada`. `make stack-check` passed: 231 backend tests and 191 frontend tests, with mypy and the linters clean.
  
  **What changed.** Before, every open stream read the event on each notification in its own thread and database connection. That meant 3 viewers of one event made 3 reads and opened 3 connections at once; the new test caught exactly that before the fix (3 different Postgres PIDs). Now the listener in [realtime.py](backend/events/realtime.py) keeps one shared reader per event and snapshot function. It reads once per notification and passes the result to all subscribers. If a notification arrives while a read is running, it reads again afterwards. Each stream still reads its own first snapshot when it connects. If a read fails, it now ends all streams sharing it; before, it ended just the one stream that read it. The snapshot function moved to [views.py](backend/events/views.py) as a module-level `org_event_snapshot`, because sharing is keyed on the function itself. The public stream in 3.2 will get its own.
  
  **Things to look at:**
  - **Changed test expectation.** In [test_org_event_stream_api.py](backend/events/tests/test_org_event_stream_api.py), with two check-ins in a row the stream now starts reading as soon as the first notification arrives. So an intermediate snapshot (1) can come before the final one (2). The test now waits for the final snapshot rather than requiring the very next one to be final. It still fails if the count never reaches 2. This matches the invariant in the spec ("the last snapshot is correct"), but it's a looser check than before.
  - **Test connection cleanup.** The stream test's check-in now closes its own database connection. Before, the stream's next read happened to close it, because both ran in the same worker thread. Without the fix, the test database couldn't be dropped at the end of the run.
  - **Spec length.** I updated the backend section of [spec.md](docs/features/realtime/spec.md), and the file is now 160 lines, over the 150-line limit. It was already near the limit before this change.
  - **Session log.** The previous session had no end marker, so I closed it at 21:05, the time of the last commit, in [decisions.md](docs/decisions.md). That file also records the reasoning for this task (the 21:19 entry).

    2. подключается поток B;
