> есть make чтобы удобно локально поднять фронт через nginx?

⏺ Отдельной цели нет, но шлюз включается переменной у обычного `make up`: compose берёт стадию из `FRONTEND_TARGET` (`build.target: ${FRONTEND_TARGET:-dev}`).
  
  ```sh
  FRONTEND_TARGET=gateway make up   # фронт через nginx на http://localhost:5173
  make up                           # обратно на Vite
  ```
  
  Учтите:
  - **Порт тот же (5173), меняется только стадия.** `make up` с другой стадией пересоздаёт контейнер `frontend`. Если раньше шлюз уже собирался, обе стадии берутся из кэша.
  - **Это сборка, а не dev-сервер.** Правки фронтенда сами не подхватятся, после каждой нужно снова `FRONTEND_TARGET=gateway make up`.
  - **Ваш режим `make dev-frontend` + `make dev-backend` к шлюзу не подключить.** nginx внутри compose проксирует на сервис `backend` из compose, а не на ваш локальный uvicorn. Шлюз работает только со стеком `make up` целиком.
  - Если база новая — потом ещё `make demo-users`.
  
  Могу добавить короткую цель, например `make up-gateway` (то же самое под понятным именем), со строкой в `docs/development.md`. Это отдельный маленький коммит в новой ветке от `main` после слияния PR #20 или прямо в эту ветку, пока PR открыт. Нужно?

⏺ Сделать можно. Но готовый шлюз так не подойдёт: его nginx жёстко проксирует на `http://backend:8000`, то есть на сервис из compose, а при `make dev-backend` backend — ваш локальный uvicorn на `127.0.0.1:8000`. Предлагаю так:
  
  **`make dev-frontend-nginx`** — замена `make dev-frontend` на том же :5173, в пару к `make dev-backend`:
  1. `vite build --watch` локально: `frontend/dist` пересобирается при каждой правке (HMR нет, после пересборки — F5).
  2. nginx в Docker — тот же образ `nginx:1.30.6-alpine` и тот же конфиг, что у шлюза e2e, с `frontend/dist`, подключённым как том. Контейнер запускается с `--network host`: так nginx достаёт до uvicorn на `127.0.0.1:8000`, а сам uvicorn трогать не нужно. В вашем окружении (Docker Engine в WSL2) это работает.
  3. Ctrl+C останавливает сборку и удаляет контейнер.
  
  Что придётся поменять:
  - **`frontend/nginx.conf`.** Адрес backend станет переменной: `proxy_pass ${BACKEND_URL}` через штатные шаблоны образа nginx (`/etc/nginx/templates`). Шлюз в compose получит `BACKEND_URL=http://backend:8000`, и для e2e ничего не изменится. Нужно ещё проверить, что nginx-переменные вроде `$uri` и `$http_host` при подстановке не пострадают.
  - **Документация.** Цель — в `make help` и `docs/development.md`, и там оговорка: `--network host` работает в Linux и WSL2, но не в Docker Desktop на macOS.
  
  Это вне фаз: отдельная ветка от `main` и PR без префикса, PR #20 не трогаю.
