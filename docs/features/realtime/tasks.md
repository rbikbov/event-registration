# Realtime (SSE): задачи

Spec — `spec.md`. Одна задача — один коммит; отметка `[x]` — в том же коммите.

Этапы вертикальные: каждый заканчивается тем, что можно показать в браузере. Внутри этапа —
backend → frontend → e2e/доки. Логика — тест вперёд; в каждой задаче `make stack-check`.

## Этап 1. Живой счётчик «Пришло» на панели (tracer bullet)

- [x] 1.1 backend: `pg_notify` в `check_in` (первая отметка), слушатель на процесс,
      `GET /api/org/events/{id}/stream/` (DRF-view, по пути api-change) — снимок при
      подключении и на уведомление; 403/404.
      Готово, когда: тесты «уведомление после коммита, нет после отката», «первое сообщение —
      снимок», «чекин → новый снимок», «повторный чекин без уведомления», 403/404 зелёные.
- [x] 1.2 frontend: composable потока в `shared/lib`, панель пишет снимок в кэш
      `orgEventQuery(id)`. Готово, когда: Vitest с подменённым `EventSource` зелёный; в
      браузере (Vite) чекин в одной вкладке меняет «Пришло» в другой.

## Этап 2. Шлюз nginx

- [x] 2.1 infra: стадия `gateway` в `frontend/Dockerfile` — `vite build` и nginx на 5173,
      прокси `/api`, `/admin`, `/static`, fallback на `index.html`; `FRONTEND_TARGET` в
      compose, `make e2e`, `stack-e2e` и CI — через `gateway`; uvicorn с
      `--timeout-graceful-shutdown` — в Docker и в `make dev-backend` (`--reload` иначе ждёт
      открытые потоки без конца); `development.md`. Готово, когда: `make stack-e2e`
      зелёный через шлюз; `curl -N` потока через шлюз получает снимок сразу, а без
      `X-Accel-Buffering: no` — нет (проверено и записано в лог). Замер: без заголовка
      снимки тоже идут сразу, задерживает только буферизация с gzip — spec, п. 3.
- [ ] 2.2 e2e: два контекста организатора — чекин в одном, «Пришло» меняется в другом без
      перезагрузки. Готово, когда: тест зелёный и падает, если поток не подключён.

## Этап 3. Все изменения счётчиков, страница события, таблица участников

- [ ] 3.1 backend: потоки — асинхронные view (способ — открытый вопрос spec, п. 1), снимок
      читается один раз на событие и уведомление для всех подписчиков процесса. Готово, когда:
      тесты потока зелёные; замер — открытые потоки не добавляют потоков ОС; при N
      подписчиках на одно уведомление — один запрос снимка.
- [ ] 3.2 backend: `pg_notify` в `register` и `cancel` (с повышением);
      `GET /api/events/{id}/stream/` — снимок публичного события. Готово, когда: тесты «одно
      уведомление» на регистрацию, оживление, отказ с повышением и «без уведомления» на
      повторы зелёные.
- [ ] 3.3 backend: `?page=` (по 50) у `GET /api/org/events/{id}/registrations/`, счётчик
      `cancelled` у события организатора (в `GET` и снимке). Готово, когда: тесты страниц,
      номера в листе на второй странице, `page` < 1 → 400, число запросов не зависит от
      числа строк — зелёные.
- [ ] 3.4 frontend: макет события организатора — маршрут `/org/events/:id` с дочерними
      «участники» (`""`) и «чекин» (`checkin`): в макете один `GET` события, поток, шапка
      (название, счётчики; у чекина — одной строкой), 403/404 и вкладки; событие дочерним —
      пропсом через `RouterView`. Форма чекина работает и без события (исключение п. 4
      `frontend/AGENTS.md`); отмена `GET` экрана чекина в обработчике снимка больше не нужна.
      Готово, когда: Vitest макета и обеих дочерних зелёный; `organizer-checks-in.spec.ts`
      проходит; переход «чекин ↔ участники» не переоткрывает поток.
- [ ] 3.5 frontend: страница события — один `GET`, затем снимки из потока; таблица панели —
      постранично, число страниц — из счётчиков снимка, снимок с другими счётчиками
      показывает «Есть обновления — обновить». Готово, когда: Vitest зелёный.
- [ ] 3.6 e2e: регистрация в одном контексте меняет «свободно мест» на странице события в
      другом и показывает «Есть обновления» на панели; чекин в одном контексте меняет «Пришло»
      на экране чекина в другом. Готово, когда: тест зелёный.

## Этап 4. Обрыв и переподключение

- [ ] 4.1 backend: `: ping` каждые 15 с, `retry: 3000`, обрыв слушателя закрывает потоки
      процесса. Готово, когда: тесты heartbeat и обрыва слушателя зелёные.
- [ ] 4.2 frontend: индикатор «Соединение потеряно, переподключаюсь…» на панели; повторное
      открытие закрытого потока через 3 с, если он хоть раз открывался; `useLive` на
      `pagehide` с `persisted` отписывается, на `pageshow` с `persisted` подписывается заново
      (страница из bfcache: поток закрыт, а `GET` панель не делает). Готово, когда: Vitest
      «обрыв → индикатор → снимок → без индикатора», «502 → переоткрытие» и «pageshow из
      bfcache → новая подписка» зелёный; в браузере через шлюз — «Назад» после полной
      загрузки другого события показывает живые счётчики.
- [ ] 4.3 e2e: поток прерван через `page.route` — индикатор виден; восстановлен — индикатор
      пропал, счётчик верен. Готово, когда: тест зелёный.
- [ ] 4.4 закрытие фазы: критерии по фактам, `architecture.md` («Процессы», «API», «Realtime»,
      экраны) — «реализовано», README. Готово, когда: `make stack-check` и `make stack-e2e`
      зелёные.
