# Чекин и статистика организатора: spec

Фаза — `docs/roadmap.md`, фаза 3. Статус: утверждён 2026-10-31.

## Что и зачем

Закрывает из `docs/task.md` «билет с кодом и экран чекина на входе» и «билет проходит чекин
один раз», а также счётчики организатора (обновление live — фаза 4). Организатор вводит код
с билета и получает крупный ответ; на панели события видит счётчики и участников. Чекин —
одно атомарное изменение строки, поэтому одновременные запросы с одним кодом дают ровно один
успех. Отказ от отмеченного билета запрещён (решение от 2026-10-31 06:09). Отправная точка —
«Инварианты и конкурентность» и «API» в `docs/architecture.md`; ответ чекина spec изменил
(«Допущения», п. 1), `architecture.md` приведён к spec.

## Non-Goals

- Живое обновление счётчиков, SSE — фаза 4: панель перечитывает данные при открытии.
- Снятие отметки, чекин вручную по имени, сканер QR — вход только по коду.
- Окно чекина по времени события: отметить можно в любой момент.
- Редактирование события и лимита — фаза 5. Пагинация, поиск, сортировка списка участников.
- Повышение из листа ожидания при неявке, экспорт списка.

## Модель данных

- **Registration**: `checked_in_at` timestamptz null. `CHECK (checked_in_at IS NULL OR
status = 'confirmed')` — отмеченный билет не бывает отменённым или в листе. Миграция
  добавляет nullable-поле и ограничение; существующие строки ему удовлетворяют.
- Счётчик «пришло» — `confirmed` с `checked_in_at IS NOT NULL`, в
  `EventQuerySet.with_registration_counts()` рядом с `confirmed` и `waitlisted`.

## API

| Метод и путь                                        | Вход                             | Ответ                                                                                                       | Ошибки (статус → `kind`)                                                                                                                                                                                |
| --------------------------------------------------- | -------------------------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/org/events/{id}/checkin/`                | `{code}`                         | 200 `{result: "checked_in" \| "already_checked_in", name, masked_email, checked_in_at}`                     | 400 → `validation` (пустой код); 403 → `forbidden` (событие другого организатора); 404 → `not_found` (нет события или нет такого кода у события); 409 → `conflict` (билет в листе ожидания или отменён) |
| `GET /api/org/events/{id}/`                         | —                                | 200 `{id, title, description, starts_at, capacity, confirmed, waitlisted, checked_in, free_seats}`          | 404 → `not_found`                                                                                                                                                                                       |
| `GET /api/org/events/{id}/registrations/?status=`   | `status` — необязательный фильтр | 200 `[{id, name, email, status, position?, checked_in_at}]` по `queued_at, id`; `position` — у `waitlisted` | 400 → `validation` (неизвестный статус); 403 → `forbidden`; 404 → `not_found`                                                                                                                           |
| `POST /api/tickets/{manage_token}/cancel/` (фаза 2) | —                                | как раньше                                                                                                  | новое: 409 → `conflict` — билет отмечен на входе; регистрация не меняется                                                                                                                               |
| `GET /api/tickets/{manage_token}/` (фаза 2)         | —                                | новое поле `checked_in_at` (null, если не отмечен)                                                          | как раньше                                                                                                                                                                                              |

- Эндпоинты организатора — сессия + CSRF. Событие другого организатора — 403, несуществующее —
  404: существование события не секрет, `GET /api/events/{id}/` публичный.
- Код нормализуется на backend: верхний регистр, без пробелов и дефисов. Код не по формату —
  404, как неизвестный.

## UI

- **Панель события** `/org/events/:id` (из списка событий организатора): название, дата,
  счётчики «мест / подтверждено / в листе ожидания / пришло / свободно», ссылка «Чекин»,
  таблица участников с фильтром по статусу. Состояния: загрузка, ошибка, «не найдено»,
  пустой список.
- **Чекин** `/org/events/:id/checkin`: поле кода с фокусом, отправка по Enter, кнопка
  блокируется на время запроса. Крупный ответ на всю ширину: «Пропущен — Имя, iv\*\*\*@gmail.com» (зелёный),
  «Уже отмечен в ЧЧ:ММ — Имя» (жёлтый), «Билет не найден» (красный), «Билет не подтверждён:
  лист ожидания или отказ» (красный), «Нет связи, повторите» (без смены последнего ответа).
  После ответа поле очищается и снова в фокусе — следующий участник.
- **Страница билета** (фаза 2): отмеченный билет — «Вы отмечены на входе в ЧЧ:ММ», кнопки
  отказа нет; отказ получил 409 (отметили, пока страница была открыта) — то же состояние после
  перечитывания.
- Время ЧЧ:ММ — в часовом поясе браузера.

## Крайние случаи

- Код другого события того же организатора — 404 «не найден»: билет не на это событие.
- Повышенный из листа: до повышения его код — 409, после — проходит. Код до оживления после
  отказа (старый `ticket_code`) — 404: оживление выдаёт новый.
- Повторный чекин того же билета — `already_checked_in` с временем первой отметки, без
  изменения строки.
- Двойной Enter — один запрос (кнопка и Enter заблокированы до ответа).

## Допущения и открытые вопросы

1. **Расходится с `architecture.md`:** там «уже отмечен» — 409, «не подтверждён» — 422.
   Здесь «уже отмечен» — 200 с `result: "already_checked_in"`, а «не подтверждён» — 409.
   Почему: для экрана чекина повтор — штатный ответ с данными (имя, время первой отметки);
   `unwrap` во фронтенде не отдаёт тело ошибки, и пришлось бы расширять `AppError` ради одного
   поля. 422 → `kind: validation` означает ошибку в форме, а здесь — состояние билета, это
   `conflict`. При утверждении `architecture.md` правится по spec.
2. Чужое событие — 403, а не 404 (решение человека): событие есть, но не ваше; скрывать
   нечего — `GET /api/events/{id}/` публичный.
3. Список участников без пагинации: масштаб демо — десятки строк.
4. В ответе чекина — имя и email с маской, собранной на backend (решение человека):
   `iv***@gmail.com` — первые два символа имени ящика (у ящика короче трёх — один), домен
   целиком. Полный адрес не уходит на экран у входа, который видит очередь, а маска помогает
   различить тёзок. Полный email — в таблице участников на панели.

## Сценарии приёмки

| Сценарий                                                                                            | Уровень теста    |
| --------------------------------------------------------------------------------------------------- | ---------------- |
| Given `confirmed` When чекин его кода Then `checked_in`, `checked_in_at` записан                    | pytest           |
| Given отмеченный When чекин снова Then `already_checked_in` с прежним временем                      | pytest           |
| Given `waitlisted` / `cancelled` When чекин Then 409; Given код чужого события Then 404             | pytest           |
| Given N потоков с одним кодом Then ровно один `checked_in`                                          | pytest, Postgres |
| Given отмеченный When отказ Then 409, статус и лист не меняются                                     | pytest           |
| Given чекин и отказ одновременно Then ровно один успех, `CHECK` не нарушен                          | pytest, Postgres |
| Given событие с участниками When панель Then счётчики и таблица; фильтр по статусу                  | pytest, Vitest   |
| Given экран чекина When ответы 200 / 404 / 409 / сеть Then свой крупный ответ                       | Vitest           |
| Given билет из письма When чекин дважды Then «пропущен», затем «уже отмечен»; на панели «пришло: 1» | e2e              |
